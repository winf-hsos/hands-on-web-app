farmer Jeff wants a flyer with this week's offers: is a chat enough, or does it take an agent?
image: AI-generated (gpt-image-2.5-flare)
Jeff betreibt den Lindenhof, einen kleinen Hofladen mit Selbstbedienung. Diese Woche will er einen Flyer mit den Angeboten aushängen: Eier, Honig, Kartoffeln, Grünkohl. Ein Chat wie ChatGPT schreibt ihm einen schönen Text, aber den Flyer als Datei, die Preise aus einer Liste oder ein Programm, das die Rabatte rechnet, bekommt er dort nicht. Heute lernen wir das Werkzeug kennen, mit dem wir ab jetzt arbeiten, OpenCode, und sehen, was aus einem Chat einen Agenten macht. Laden und Preise sind ausgedacht.

a chat answers, an agent works on the task

Links ein Chat, wie ihr ihn kennt: Ihr schreibt etwas, das Sprachmodell schreibt Text zurück, fertig. Rechts ein Agent. Er benutzt dasselbe Sprachmodell, aber das Modell darf Werkzeuge aufrufen: Dateien lesen und schreiben, Befehle ausführen, im Web suchen. Das Ergebnis jedes Aufrufs geht zurück ans Modell, und das Modell entscheidet, ob es fertig ist oder noch etwas tun muss. Diese Schleife ist der ganze Unterschied. Das Modell selbst tut nichts, es schreibt nur auf, welches Werkzeug es aufrufen will, und OpenCode führt den Aufruf aus.

one app, two models

OpenCode bringt kein eigenes Sprachmodell mit. Es schickt eure Eingaben an einen Anbieter und zeigt die Antwort. Wir verbinden zwei: OpenAI mit gpt-6-luna, ein großes Modell in der Cloud, dafür braucht ihr den Schlüssel aus dem Kurs; und LM Studio mit gemma-4-e2b, ein kleines Modell auf eurem eigenen Laptop. LM Studio müsst ihr nicht verbinden: Läuft sein Server, findet OpenCode ihn unter 127.0.0.1:1234 von selbst. Der gestrichelte Rahmen ist euer Laptop: Mit luna verlässt alles, was ihr schreibt, den Rechner, mit gemma bleibt es dort. Dafür ist gemma langsamer und macht mehr Fehler, wie wir gleich sehen.

four words you meet in OpenCode

project
a folder on your laptopthe agent reads and writes only there
session
one conversation in that folderit has its own context, a new session starts empty
agent
a role for the model with its own permissionsthe built-in agent Build may change files and run commands, Plan may only read and plan
model
the language model that answerschosen below the input field, and switchable in the middle of a session
Vier Begriffe, die ihr in OpenCode ständig seht. Ein Projekt ist ein Ordner, für uns der Ordner lindenhof. Eine Sitzung ist ein Gespräch in diesem Ordner, mit eigenem Gedächtnis; eine neue Sitzung weiß nichts von der alten. Ein Agent ist in OpenCode eine Rolle für das Modell: eigene Anweisungen und eigene Rechte, welche Werkzeuge es benutzen darf. Zwei sind eingebaut: Build darf Dateien ändern und Befehle ausführen, Plan darf nur lesen und Pläne vorschlagen. Eigene Agenten legt man in einer Konfigurationsdatei an, das machen wir im Hofladen-Experiment. Und das Modell wählt ihr unter dem Eingabefeld, und zwar auch mitten in einer Sitzung; das brauchen wir später, wenn das kleine Modell scheitert.

AGENTS.md: what the agent reads first

lindenhof/AGENTS.md
# Lindenhof farm shop You help Jeff, who runs the Lindenhof farm shop, a small self-service shop on his farm. Customers weigh, pay and take their goods themselves. - Answer in English and keep it short. - Write every file into this folder. - Prices are in euros with two decimals, such as 6.50.
OpenCode puts this file in front of everything you type, in every session of the folder; /init writes a first version.
Die Datei AGENTS.md beschreibt dem Agenten den Ordner: wer hier arbeitet, worum es geht, welche Regeln gelten. OpenCode liest sie zu Beginn jeder Sitzung und stellt sie vor alles, was ihr schreibt. Den ersten Entwurf schreibt der Befehl /init; wir ersetzen ihn durch diesen Text. Fragt ihr danach in einer neuen Sitzung, für wen der Agent arbeitet, antwortet er als Helfer von Jeff, ohne dass ihr in dieser Sitzung ein Wort über den Laden gesagt habt.

Fragt den Agenten, welche Werkzeuge er hat, und er zählt sie auf. Er kennt sie, weil OpenCode mit jeder Anfrage eine Beschreibung jedes Werkzeugs mitschickt. In unserem Test waren es diese 14. what OpenCode sends when you type hi

the agent sends its instructions and every tool description before you have typed a word.
a new session of the agent Build with gemma-4-e2b, read in the server log of LM Studio with verbose logging
Das sieht man in LM Studio, wenn man unter Model Server das ausführliche Protokoll einschaltet. Wir schicken nur „hi“. Im Protokoll steht die ganze Anfrage: vorn ein Systemprompt von OpenCode mit rund 25.000 Zeichen, darin die Regeln, wie der Agent arbeiten soll, und eure AGENTS.md; dann die Beschreibungen der 14 Werkzeuge, noch einmal rund 18.000 Zeichen; und ganz am Ende das „hi“, zwei Zeichen. Das alles geht mit jeder einzelnen Anfrage an das Modell.

three things the agent does in your folder

read and write files
read · write
it works with the files in your folder, such as offers.md, with nothing to upload or download
look something up
websearch · webfetch
the agent read a seasonal calendar on the web and named its source
run a program
write · shell
it wrote prices.py, ran it on your laptop and read the output, and fixes the file if the program fails
a click on the grey lines in the session, such as “used 1 write”, shows every tool call with what went in and what came out.
Drei kleine Aufgaben im Ordner. ChatGPT kann inzwischen auch suchen und Python ausführen, aber in seiner eigenen Umgebung in der Cloud; der Agent arbeitet auf eurem Laptop, mit euren Dateien und euren Programmen. Erstens Dateien lesen und schreiben: Der Agent legt offers.md direkt im Ordner an, ohne Hochladen und Herunterladen. Zweitens nachschlagen: In unserem Test hat er zweimal gesucht, den Saisonkalender von regional-saisonal.de gelesen und Grünkohl, Rosenkohl, Lauch und Feldsalat genannt; ob er richtig gelesen hat, prüft ihr. Drittens ein Programm schreiben und auf eurem Laptop ausführen: prices.py liest die Angebote, gibt zehn Prozent Rabatt über fünf Euro und druckt die Liste. Geht das Programm schief, liest der Agent die Fehlermeldung und versucht es noch einmal; und zwar mit dem Python, das auf eurem Rechner installiert ist.

Typst ist ein Programm, das aus einer Textdatei ein PDF macht, ähnlich wie LaTeX, aber einfacher. Es verzeiht keinen Fehler: Stimmt die Schreibweise nicht, kommt kein PDF heraus, sondern eine Fehlermeldung. Was glaubt ihr?

the small model writes Markdown into a Typst file

flyer.typ by gemma-4-e2b, first attempt
# Lindenhof Farm Shop Offers This Week! ## Fresh Eggs 0.40 euros each ## Honey 6.50 euros per jar
error: expected expression
what Typst expects
= Lindenhof Farm Shop Offers This Week! == Fresh Eggs 0.40 euros each == Honey 6.50 euros per jar
flyer.pdf
Das ist der erste Versuch von gemma-4-e2b, wörtlich, nur gekürzt. Das Modell schreibt Markdown, wie es das aus unzähligen Texten kennt: Raute für Überschriften, Sternchen für Fettdruck. In Typst beginnt mit der Raute aber ein Befehl, deshalb bricht typst compile gleich in der ersten Zeile ab. Typst erwartet für Überschriften Gleichheitszeichen. Ein winziger Unterschied, den das kleine Modell nicht findet.

the same session, two models

the larger model needed only three words, because the whole session with every error message was still in its context.
real runs in OpenCode 2.4.1, the answer of gemma-4-e2b shortened
Oben, was gemma-4-e2b getan hat: Es schreibt die Datei, kompiliert, bekommt den Fehler, schreibt die Datei fünfmal neu, ohne zu kompilieren, kompiliert wieder, Fehler, schreibt zweimal neu, Fehler. Jedes Mal Markdown. Zum Schluss entschuldigt es sich und sucht den Fehler beim Compiler und bei den Werkzeugen, nicht bei sich. Dann wechseln wir in derselben Sitzung auf gpt-6-luna und schreiben nur „Fix the error.“ Luna liest die Datei, ändert sie, kompiliert, fertig, in etwa 15 Sekunden. Mehr Erklärung brauchte es nicht, weil die ganze Sitzung mit allen Versuchen und Fehlermeldungen im Kontext stand.

Sprachmodelle zählen nicht in Zeichen, sondern in Tokens, Wortstücken von etwa vier Zeichen. Die 43.000 Zeichen von eben sind gut zehntausend Tokens. So viel kostet jede Anfrage, bevor ihr irgendetwas gefragt habt.

the context window has to hold everything

a model that is enough for a chat in LM Studio can be too small for an agent.
the error in OpenCode: request (10581 tokens) exceeds the available context size (8192 tokens)
Das Kontextfenster ist die Menge Text, die ein Modell auf einmal sehen kann. Beim Laden in LM Studio legt ihr es fest. Mit 8.192 Tokens, dem Standard, wenn man nichts einstellt, passt schon die Anfrage zu „hi“ nicht hinein: OpenCode zeigt einen Fehler statt einer Antwort. Mit 32.768 passt sie, und es bleibt Platz für das Gespräch und für die Dateien, die der Agent liest. Je größer das Fenster, desto mehr Speicher braucht das Modell auf eurem Laptop.

/compact makes room

a long session costs more with every message, because the whole conversation goes to the model again each time.
Ein Sprachmodell merkt sich nichts zwischen zwei Anfragen. Damit es weiß, worum es geht, schickt OpenCode jedes Mal die ganze Sitzung mit: Systemprompt, Werkzeuge, jede Nachricht, jeden Werkzeugaufruf und jedes Ergebnis. Die Sitzung wächst, bis sie nicht mehr ins Fenster passt. /compact lässt das Modell die Sitzung zusammenfassen und macht mit der Zusammenfassung weiter. Das schafft Platz und spart Geld, aber was nicht in der Zusammenfassung steht, ist weg. Kurz vor der Grenze macht OpenCode das von selbst.

commands are for OpenCode, not for the model

/init
sets up AGENTS.md for the folder
/undo
takes back your last message, and every file the agent changed for it
/compact
summarizes the session to make room in the context
/fork
starts a new session from an earlier message, for example with another model
/new
starts a new session, also with ctrl + t
/export
saves the session with every request and every tool call
/mcp
shows the tool servers of the folder and switches them on and off
Alles, was im Eingabefeld mit einem Schrägstrich beginnt, ist ein Befehl für OpenCode und geht nicht an das Modell. Ein Schrägstrich allein zeigt alle. Diese sieben braucht ihr am häufigsten. Probiert /undo aus: Lasst den Agenten offers.md löschen und nehmt es zurück; die Datei ist wieder da, weil OpenCode vor jeder Änderung einen Schnappschuss des Ordners anlegt. /mcp ist noch leer, Werkzeugserver bauen wir in einem eigenen Experiment.

the agent in a browser

desktop app of OpenCode with gpt-6-luna
Die Desktop-App von OpenCode hat einen eigenen Browser, und ein großes Modell kann darin arbeiten: Seiten öffnen, lesen, Links folgen, Formulare ausfüllen. In der Sitzung seht ihr dabei zwei Aufrufe: skill lädt die Anleitung für den Browser, execute führt ein kleines Programm aus, das den Browser steuert. Rechts geht die Seite auf, und ihr könnt mitlesen. Ein kleines Modell wie gemma verirrt sich bei solchen Aufgaben meist, den Browser überlasst ihr dem großen.

one step further: computer use

some agents control the whole computer: they look at screenshots, move the mouse and type, in any program
OpenCode does not have this built in, it needs an extra tool server
such an agent can do everything you can, so give it only what the task needs
Manche Agenten gehen noch weiter und bedienen den ganzen Rechner: Sie sehen Bildschirmfotos, bewegen die Maus und tippen, in jedem Programm, nicht nur im Browser. OpenCode hat das nicht eingebaut; man bräuchte einen zusätzlichen Werkzeugserver. Vorsicht ist angebracht, denn ein solcher Agent kann alles, was ihr auch könnt, einschließlich Dateien löschen und Mails verschicken.

what to take away

  • an agent calls tools and reads their results until the job is done
  • AGENTS.md tells it what the folder is for
  • every request carries the system prompt and all tool descriptions
  • a small model is free and private, but fails sooner on exact tasks
  • the context window has to hold the whole session
  • check what the agent wrote, read and ran
