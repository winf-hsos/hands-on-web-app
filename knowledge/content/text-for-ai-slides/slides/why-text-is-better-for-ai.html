Anonymous. Most likely almost everyone writes in Word or Google Docs, which is no mistake; the question is whether it is the right tool once a model is meant to write along.
First a fair look at Word, then at what text files do differently.

word

Word is familiar, it has comments and track changes that supervisors use, and for many texts it is good enough. Against it: text and layout live in one file, so moving a figure can break the page; numbers from an analysis are typed or copied by hand and go stale when the data change; formulas are tedious. The point in yellow is the one this deck is about: a .docx file is not text but a packed bundle of files, and that matters as soon as a model is meant to read and change it.

text files

the source is plain text that any program and any model can read
content and layout are separate: a template sets the layout
numbers, tables and figures come from code
citations come from a .bib file in any style
one source gives pdf, html or docx
text files are not new, but with ai they gain a strength they did not have before.
Quarto, Typst and LaTeX all work with plain text files. You write the content, a template decides how it looks. Numbers, tables and figures are computed by code in the same document, so they update when the data change. Citations come from a .bib file and are formatted in whatever style the journal or the guidelines ask for. And one source gives a PDF, a web page or a Word file. All of this has been true for years; what is new is that a language model can work with such files directly, which the next part shows.
Now the reason: what a language model can do with your file.

a language model reads and writes text

A language model takes text and gives text back, nothing else. Everything else, a picture, a table, a file, has to be turned into text first, by a program around the model. A text file needs no such step: the model reads it as it is.

one sentence, two files

On the left the sentence as it stands in a Quarto file: one line, 62 bytes, the two stars make the word bold. On the right the same sentence rendered to Word: a zip archive of 16 files and more than ten kilobytes. The sentence itself sits in word/document.xml, cut into five pieces, because every change of formatting starts a new piece. To change one word there, a program has to unpack the archive, find the right piece in the XML, change it without breaking the structure, and pack everything again. A file saved by Word itself is larger still. A text file the model reads and changes line by line.

a change you can read

in a text file every change by an ai is a line you can read before you accept it.
When an AI changes a text file, the change can be shown as a diff: the line that goes in red with a minus, the new lines in green with a plus. An AI agent shows you exactly this before it writes to your file, and you accept or reject it. In a Word file the same change happens inside the packed XML, and you see the result, not the change.
Three formats for writing scientific texts as text. They differ in syntax but share the idea.

the same four things, three times

A heading, a bold word, a formula and a citation, in each of the three. Quarto uses Markdown, the lightest syntax: a hash for a heading, two stars for bold, an at sign in square brackets for a citation. Typst is a newer typesetting system with its own short syntax and very fast output. LaTeX has been the standard in mathematics and physics for decades and is the most verbose of the three. All three keep formulas as text, and all three take citations from a .bib file.

from text to the file you hand in

You write text, and an engine sets it into the format you hand in. Quarto reads Markdown with code, runs the code and can produce a web page, a Word file or a PDF; for the PDF it hands the text on to Typst or LaTeX. Typst and LaTeX set PDF directly. So writing in text does not mean giving up Word: if a supervisor wants a .docx to comment on, Quarto produces it from the same source.
Last part: what this means for a report in Quarto.

numbers from code

a number that comes from code can be mistyped neither by you nor by an ai.
In Quarto a number in the text can come straight from R: the chunk computes the median, and the inline expression writes it into the sentence. When the data change, the number changes with it. For working with AI this matters twice: an AI that edits your text cannot invent or mistype the number, because the number is not in the text but in the code, and when you check the code, you check the number.

a report as a folder of text files

A paper in Quarto can be a small folder: a central file with the settings that pulls in the sections, one file per section and the references in a .bib file. Quarto runs the code, and Typst sets the PDF. Every file is text, so an agent can read the whole report, check one section against another and change a single line, and you see every change before it is made.
write your report as text, because then an ai can read, change and check it the same way you do.
That is the whole plea. Word stays a good tool for many texts, but for a report that grows with an analysis and that an AI helps to write, text is the better material.
