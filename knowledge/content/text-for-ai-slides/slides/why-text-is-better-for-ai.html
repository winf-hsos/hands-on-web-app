A plea for writing a paper as text, in Quarto, Typst or LaTeX, instead of in Word. The one sentence to take home: a language model reads and writes text, so a report that is text can be read, changed and checked by a model in the same way as by you.
Four parts: what you probably write with today, what a language model actually sees when it reads your file, three text formats side by side, and what this means for a report in Quarto.

Two ways to hand over the same words. In the notebook everyone can read every line at once, point at a sentence and change it with a pencil. The parcel holds the same text, but before anyone can read or change a word, it has to be unpacked, and afterwards packed again so that nothing gets lost. For a language model, a Word file is the parcel and a text file is the notebook.
First a fair look at Word, its strengths and its weaknesses, then at what text files do differently.

word

Word is familiar, it has comments and track changes that supervisors use, and for many texts it is good enough. Against it: text and layout live in one file, so moving a figure can break the page; numbers from an analysis are typed or copied by hand and go stale when the data change; formulas are tedious. The point in yellow is the one this deck is about: a .docx file is not text but a packed bundle of files, and that matters as soon as a model is meant to read and change it.

text files

text files are not new, but with ai they gain a strength they did not have before.
Quarto, Typst and LaTeX work with plain text files. The first click shows a paper.qmd open in Positron, where you and an AI agent write in the same file at the same time: your lines in white, the agent's in blue, text and an R chunk and a citation side by side. Only the content is written here, nothing about fonts or margins. The second click brings in the layout: a template decides how it looks, and Quarto renders the same source to a PDF, a Word file or a web page, runs the code on the way, takes the citations from a .bib file in whatever style is needed. All of this has been true for years; what is new is that a language model can work in such files directly, which the next part shows.
Now the reason: what a language model can do with your file.

a language model reads and writes text

A language model takes text and gives text back, nothing else. The first click sends a prompt with paper.qmd attached: the file is text, so the model reads it at once and answers. The second click sends the same prompt with paper.docx. The model cannot read the packed file, so an agent first writes a small Python script that opens the archive with the package python-docx and prints the paragraphs, runs it and only then reads the text. Chat tools do the same behind the scenes, with a converter that turns the file into text first, and what gets lost on the way, such as comments, tracked changes or the position of a figure, the model never sees.

one sentence, two files

On the left the sentence as it stands in a Quarto file: one line, 62 bytes, the two stars make the word bold. On the right the same sentence rendered to Word: a zip archive of 16 files and more than ten kilobytes. The sentence itself sits in word/document.xml, cut into five pieces, because every change of formatting starts a new piece. To change one word there, a program has to unpack the archive, find the right piece in the XML, change it without breaking the structure, and pack everything again. A file saved by Word itself is larger still. The next three clicks mark the three pieces of the sentence on both sides: "Women name a", then "higher", then "price than men.". Everything is there, but scattered between tags, so a model has to read the markup around every word to find the sentence, while in the text file it simply reads the line.

a change you can read

in a text file every change by an ai is a line you can read before you accept it.
When an AI changes a text file, the change can be shown as a diff: the line that goes in red with a minus, the new lines in green with a plus. An AI agent shows you exactly this before it writes to your file, and you accept or reject it. In a Word file the same change happens inside the packed XML, and you see the result, not the change. The same diffs are what version control works with: git keeps every change to a text file as a version you can compare and go back to, while for a .docx it only knows that the file has changed.
Three formats for writing scientific texts as text. They differ in syntax but share the idea.

the same four things, three times

A heading, a bold word, a formula and a citation, in each of the three. Quarto uses Markdown, the lightest syntax: a hash for a heading, two stars for bold, an at sign in square brackets for a citation. Typst is a newer typesetting system with its own short syntax and very fast output. LaTeX has been the standard in mathematics and physics for decades and is the most verbose of the three. All three keep formulas as text, and all three take citations from a .bib file.

from text to the file you hand in

You write text, and an engine sets it into the format you hand in. Quarto reads Markdown with code, runs the code and can produce a web page, a Word file or a PDF; for the PDF it hands the text on to Typst or LaTeX. Typst and LaTeX set PDF directly. So writing in text does not mean giving up Word: if a supervisor wants a .docx to comment on, Quarto produces it from the same source.
What this means for a report in Quarto, where text and code live in the same document.

numbers from code

a number that comes from code can be mistyped neither by you nor by an ai.
In Quarto a number in the text can come straight from R: the chunk computes the median and formats it with two decimals, and the inline expression writes it into the sentence. The second click shows a real cut-out of the PDF that Quarto and Typst make of it, with the number marked. When the data change, the number changes with it. For working with AI this matters twice: an AI that edits your text cannot invent or mistype the number, because the number is not in the text but in the code, and when you check the code, you check the number.

a report as a folder of text files

A paper in Quarto can be a small folder, and the clicks walk through it. paper.qmd is the main document: it holds the settings and pulls in the sections in their order. references.bib is your literature, one entry per source, from which Quarto formats every citation. The folder sections holds one file per section, with text and code. The last click renders the whole folder into one PDF. Quarto runs the code, and Typst sets the PDF. Every file is text, so an agent can read the whole report, check one section against another and change a single line, and you see every change before it is made.
One step further: not only the file has to be text, the tool should also bring a command line, because that is where an agent works.

an agent works in the terminal

an ai uses a tool with a command line the same way you do, and quarto, typst and latex all bring one.
An AI agent works in a terminal: it types a command, reads what comes back and decides on the next step. Quarto, Typst and LaTeX each bring such a command, so an agent can render the paper, read the error messages and fix the source on its own. Word has menus and buttons but no command to render or change a document; there are detours such as Pandoc or scripts that remote-control Word, but Word itself is built for a person with a mouse. "Meet the AI where it lives" means: a tool that wants to be used by AI comes to the terminal and to text files.

the same idea elsewhere

More and more tools follow the same idea. Excalidraw keeps every drawing as JSON text and publishes an official command line interface "for humans and agents", which renders drawings and turns Mermaid text into editable drawings. Mermaid writes a diagram as text, and GitHub, Quarto and Excalidraw draw it. Marimo saves a notebook as a plain Python file instead of a JSON file with outputs and images inside. The GitHub CLI brings issues, pull requests and releases to the terminal. A CSV file is a table as plain text, while an .xlsx file is a packed bundle like a .docx. And this deck itself is an HTML file and a script, so an AI can build and change it in the same way as a paper in Quarto.
