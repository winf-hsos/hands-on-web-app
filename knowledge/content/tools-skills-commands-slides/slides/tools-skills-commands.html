Der Lindenhof ist ein kleiner Hofladen mit Selbstbedienung: Die Inhaberin füllt die Regale, die Kundschaft wiegt, zahlt und nimmt selbst. Zwei Arbeiten kommen immer wieder: jede Woche die Bestellung bei den Lieferanten und jeden Abend der Kassenabschluss. Ein KI-Agent könnte beides übernehmen, aber noch kann er keine der beiden. Heute rüsten wir ihn Stück für Stück aus und sehen jedes Mal nach, was sich ändert. Laden und Zahlen sind ausgedacht.

one agent, three groups of tools

Das ist der Startordner des Experiments. In opencode.jsonc steht ein Agent namens shop mit einem Modell, einer Rolle in einem Satz und den Regeln, was er darf. Daneben drei Gruppen von Werkzeugen in einem kleinen Python-Programm: shop liest Produkte, Bestand und Verkäufe, orders schickt eine Bestellung, till liest Kasse und Kassenbox und schreibt das Kassenbuch. Zu Beginn sind alle drei ausgeschaltet, und die erste Regel nimmt dem Agenten alles, was OpenCode sonst mitbringt: keine Dateien, keine Shell, kein Web.

the naked agent

without tools, a model can only ask back or guess, because it cannot see anything of the shop.
Das ist die echte Antwort von gpt-6-luna. Sie ist vernünftig: Das Modell weiß nichts über den Laden und fragt nach. Ein kleineres Modell rät an dieser Stelle gern und erfindet Produkte und Mengen. Beides ist keine Bestellung. Frage an den Saal: Was bräuchte der Agent als Erstes?

a tool is a function the agent may call

sales(from_date, to_date) Units sold of each product between two dates, both included. call sales(from_date="2026-10-27", to_date="2026-11-23") result {"days_open": 24, "units_sold": {"milk": 162, "yoghurt": 96, "butter": 61, …}}
Ein Werkzeug ist eine Funktion mit Namen, Parametern und einer Beschreibung in Worten. Das Modell sieht nur diese Beschreibung, nicht den Code. Es schreibt einen Aufruf, OpenCode führt ihn aus und legt das Ergebnis zurück in den Kontext. Die Zahlen hier sind die Verkäufe der vier Wochen vor dem Testtag; sie werden aus dem Datum erzeugt, deshalb bekommt jede Gruppe am selben Tag dieselben.

switching a group of tools on

"mcp": { "servers": { "shop": { "type": "local", "command": ["python", "tools/farm_shop.py", "shop"], "disabled": false }, …
Die Werkzeuge laufen als MCP-Server, also als eigenes Programm, das OpenCode startet und mit dem es über ein festes Protokoll spricht. Eingeschaltet wird eine Gruppe, indem man disabled auf false setzt. OpenCode merkt die Änderung selbst; in einer neuen Sitzung sind die Werkzeuge da. Unter macOS und Linux steht dort python3.

what a tool may do

allow
the agent calls the tool whenever it decides to
ask
opencode stops before every call and asks the person
deny
the tool is gone, the model does not even see it
Die Regeln stehen als Liste in opencode.jsonc, und die letzte passende Regel gilt. Lesen darf der Agent frei, shop und till stehen auf allow. Bestellen kostet Geld und lässt sich nicht zurücknehmen, deshalb steht orders auf ask. Deny ist mehr als ein Verbot: Ein verweigertes Werkzeug verschwindet aus dem Kontext, das Modell weiß nicht einmal, dass es existiert. So startet der nackte Agent.

a skill is a file with know-how

.agents/skills/weekly-order/SKILL.md --- name: weekly-order description: How the Lindenhof farm shop works out its weekly order to the suppliers. Use it whenever an order or restocking is due. --- 1. Get the sales of the last four weeks with `sales` … 2. The target stock is the average per week times 1.5 …
Ein Skill ist eine Markdown-Datei in einem Ordner mit festem Namen. Oben stehen Name und Beschreibung, darunter die Schritte in normaler Sprache, so wie die Inhaberin sie einer Aushilfe erklären würde. Kein Code, keine neue Fähigkeit, nur Wissen darüber, wie dieser Laden die Arbeit macht. Die vollständige Datei steht im Experiment.

the agent loads a skill only when it needs it

Das ist der Kontext des Agenten zu Beginn: Rolle, Werkzeuge, und vom Skill nur Name und Beschreibung, eine Zeile. Erst wenn die Frage zur Beschreibung passt, ruft das Modell das Werkzeug skill auf, und dann kommt der ganze Text in den Kontext. So kann ein Agent Dutzende Skills kennen, ohne dass sein Kontext voll wird. Deshalb ist die Beschreibung so wichtig: Sie entscheidet, wann der Skill geladen wird.

with the skill, both runs follow the shop's rules

a skill turns a model that invents its own rules into one that follows the rules of this shop.
Dieselbe Frage, zwei neue Sitzungen, jetzt mit dem Skill: Beide Läufe sehen vier Wochen an, beide kommen auf genau die Mengen, die das Lösungsskript ohne Sprachmodell ausrechnet, und beide lassen den eigenen Hof weg. Nichts an den Werkzeugen hat sich geändert.

a command is a prompt with a short name

.opencode/commands/weekly-order.md --- description: Work out this week's order and place it after you agree agent: shop --- Work out this week's order with the skill weekly-order, for these suppliers: $ARGUMENTS If no supplier is named, do it for all of them. Show me the table first and place one order per supplier only after I have agreed.
Ein Command ist eine Markdown-Datei mit einem Prompt, den man sonst jede Woche neu tippen würde. Der Dateiname wird zum Befehl, $ARGUMENTS ist der Platz für das, was hinter dem Befehl steht. Der Command nennt den Skill ausdrücklich; so muss sich das Modell nicht darauf verlassen, dass es ihn selbst findet.

what opencode sends to the agent

Man tippt eine Zeile, OpenCode liest die Datei, setzt den Rest der Zeile für $ARGUMENTS ein und schickt den ganzen Text an den Agenten. Das Modell sieht keinen Befehl, sondern nur einen ausführlichen Prompt. Danach läuft alles wie vorher: Skill laden, Werkzeuge aufrufen, Tabelle zeigen, und bei der Bestellung fragt OpenCode nach, weil orders auf ask steht.

who decides when each part comes in

tool
the model decides when to call it · the permission decides whether it may
skill
the model loads it when the description fits · or a command names it
command
a person types it · the model never starts one by itself
Das ist der eigentliche Unterschied zwischen den drei Teilen. Werkzeuge und Skills setzt das Modell selbst ein, eingeschränkt durch die Regeln in der Konfiguration. Einen Command startet nur ein Mensch. Wer einen Ablauf zuverlässig in Gang setzen will, schreibt einen Command; wer will, dass der Agent etwas von selbst richtig macht, schreibt einen Skill.

the daily closing, in the owner's words

every morning the cash box starts with 100 euros of change. customers pay cash into the box or by card at the self-service till; card payments never reach the box. whoever brings back a glass bottle or jar takes 15 cents of deposit out of the box. in the evening i count the box and compare it with what should be in it. a difference of up to two euros either way is fine, anything more i want to hear about. then the day goes into the cash book.
Für den zweiten Ablauf schreibt niemand mehr selbst einen Skill. Die Gruppen bekommen nur diese Beschreibung der Inhaberin und lassen den Agenten daraus Skill und Command schreiben. Die Werkzeuge der Gruppe till sind da: register_log für die Umsätze, cash_count für das gezählte Geld und write_cashbook für das Kassenbuch.

two rules let the agent write, but only skills and commands

{ "action": "edit", "resource": ".agents/skills/**", "effect": "ask" }, { "action": "edit", "resource": ".opencode/commands/**", "effect": "ask" }
Die beiden Regeln stehen im Startordner schon in opencode.jsonc, auskommentiert. Sie geben dem Agenten ein Schreibwerkzeug, aber nur für zwei Ordner, und mit ask zeigt OpenCode jede Datei, bevor sie entsteht. Kassenbuch, Werkzeuge und die eigene Konfiguration bleiben für den Agenten tabu; sonst könnte er sich seine Rechte selbst erweitern.

the skill the agent wrote

1. Retrieve that day's till register log and cash-box count using `till_register_log` and `till_cash_count`. 2. Calculate deposit refunds as `(returned bottles + returned jars) × €0.15`. 3. Calculate expected closing cash as `€100 opening float + cash sales − deposit refunds`. Card sales do not go into the cash box … 4. Calculate the difference as `counted cash − expected cash`. 5. Write the day to the cash book with `till_write_cashbook` … 6. If the absolute difference is greater than €2.00, tell the owner … If required source information is missing or inconsistent, ask the owner rather than guessing or recording an invented closing.
written by gpt-6-luna from the owner's words, shortened
Das hat gpt-6-luna im ersten Versuch geschrieben. Es nennt die Werkzeuge mit vollem Namen, schreibt die Rechnung als Formel und ergänzt eine Regel, die die Inhaberin nicht gesagt hat: bei fehlenden Daten nachfragen statt raten. Mit dem eigenen Command hat der Agent den Donnerstag richtig abgeschlossen, minus 4,50 Euro. Was fehlt: eine feste Form der Antwort, und der Command trägt keine Zeile agent: shop. Deshalb liest man einen Skill, den ein Agent geschrieben hat, bevor man ihn jeden Abend laufen lässt.

a strong model prepares the small one

shop
runs on gemma-4-e2b on the laptop and does the daily work
coach
runs on gpt-6-luna, reads the whole folder and rewrites skills and commands for the small model
Der Startordner hat einen zweiten Agenten, coach, mit einem starken Modell. Er darf alles im Ordner lesen und Skills und Commands umschreiben, aber nichts ausführen, und er fragt vor jeder Änderung. Man erzählt ihm, was beim kleinen Modell schiefging, und bittet ihn, die Anweisungen so genau zu machen, dass ein kleines Modell sie Schritt für Schritt befolgen kann. Statt coach geht jeder starke Agent, etwa Claude Code im selben Ordner.

the same rule, written for a small model

by hand, for gpt-6-luna
The target stock is the average per week times 1.5. For perishable products, with a shelf life of 7 days or less, it is the average times 1.0, so that nothing spoils.
by the coach, for gemma-4-e2b
Use `shelf_life_days` from `shop_products`, not the product name or your intuition. If it is 7 or less, set `target = ceil(average_per_week)`. If it is greater than 7, set `target = ceil(average_per_week * 1.5)`. In particular, yoghurt has a 14-day shelf life and uses the 1.5 multiplier.
Links der Satz aus dem Skill, den wir von Hand geschrieben haben; gpt-6-luna kommt damit aus. Rechts dieselbe Regel, wie der Coach sie für das kleine Modell geschrieben hat: welches Feld aus welchem Werkzeug, die Rechnung als Formel, und ausdrücklich der Fall, an dem das kleine Modell gescheitert ist. Die Regeln des Ladens sind dieselben; nur bleibt nichts mehr dem Urteil des Modells überlassen.

the small model with the coach's instructions

the coach fixed what it was told about, while the rest stayed as unreliable as before, so one good run is not yet a test.
one run each; gemma models in lm studio
Dieselben Aufgaben auf beiden kleinen Modellen, links vor, rechts nach dem Umschreiben durch den Coach. Die Wochenbestellung, über die wir dem Coach berichtet hatten, ist fast richtig: E4B schaut jetzt vier Wochen zurück und lässt den eigenen Hof weg, nur Joghurt stimmt nicht; E2B hat alle neun Mengen richtig, listet aber Eier und Kartoffeln vom eigenen Hof mit auf. E4B findet den Honig jetzt mit shop_stock, E2B meldet die abgelehnte Bestellung als abgelehnt. Was der Coach nicht wusste, bleibt: beide prüfen die Kasse nur mit dem Zählwerkzeug, und E2B hält das gezählte Geld weiter für den Umsatz. Manches wird sogar schlechter: E4B behauptet plötzlich, keinen Zugriff auf die Verkäufe zu haben, und E2B verrechnet sich beim Kassenabschluss und schreibt das Kassenbuch nicht. Die Lehre: jeden Fehler dem Coach melden, jede Aufgabe mehrmals laufen lassen, und Rechnungen, die immer wieder schiefgehen, in ein Werkzeug verlegen statt in den Skill.

what each part adds

tools give the agent access to the shop, a skill tells it how the shop does the job, and a command gives a person a short way to start it, and the smaller the model, the more exactly all three have to be written.
Zusammen mit dem Modell und der Schleife, die Werkzeugaufrufe ausführt und Ergebnisse zurückgibt, ist das ein Agent, der eine echte Arbeit übernehmen kann, und zwar so, wie dieser Laden sie macht. Ein großes Modell füllt Lücken in den Anweisungen selbst, ein kleines nicht; deshalb lohnt es sich, ein großes Modell die Anweisungen für ein kleines schreiben zu lassen.
