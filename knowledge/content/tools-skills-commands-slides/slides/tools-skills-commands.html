an agent with a role and nothing else

So beginnt das Experiment. Der Startordner enthält fast nichts außer der Datei opencode.jsonc, und darin steht ein Agent namens shop: ein Modell, gpt-6-luna, eine Rolle in einem Satz, und eine einzige Regel. Diese Regel nimmt dem Agenten alles, was OpenCode sonst mitbringt: Er kann keine Dateien lesen, keine Befehle ausführen und nicht im Web suchen. Alles Weitere bauen wir Schritt für Schritt dazu.

a tool is a function the agent may call

Ein Werkzeug ist eine Funktion, wie man sie aus der Mathematik kennt: Sie hat einen Namen, Eingaben und ein Ergebnis. Dazu kommt eine Beschreibung in Worten, und die ist das Einzige, was das Sprachmodell über das Werkzeug erfährt. Den Code dahinter sieht es nie. Das Modell entscheidet anhand der Beschreibung, ob das Werkzeug zur Frage passt, und füllt die Eingaben aus, hier zwei Daten. Das Ergebnis ist Text, meist im Format JSON, und geht zurück an den Agenten.

in the chat: the agent calls a tool

real run of gpt-6-luna in opencode; it also called shop_products first, left out here
So sieht das in OpenCode aus. Jeff stellt eine Frage in normaler Sprache. Das Modell erkennt, dass shop_sales passt, rechnet selbst aus, welche Daten „die letzten vier Wochen“ sind, und schreibt den Aufruf. OpenCode führt ihn aus, nicht das Modell, und gibt das Ergebnis zurück. Erst dann formuliert das Modell die Antwort. Der Name shop_sales entsteht so: shop ist die Gruppe, sales das Werkzeug.

everything becomes part of the context

Das Modell selbst merkt sich nichts. Was es sieht, ist ein einziger langer Text, der Kontext: oben die Rolle, dann die Liste der Werkzeuge mit ihren Beschreibungen, dann Jeffs Frage. Ruft das Modell ein Werkzeug auf, hängt OpenCode den Aufruf und das Ergebnis an diesen Text an, und erst mit diesem längeren Text schreibt das Modell seine Antwort. Jedes Werkzeugergebnis kostet also Platz im Kontext, und alles, was im Kontext steht, kann das Modell verwenden.

where do the tools come from?

Die Werkzeuge stecken nicht in OpenCode, sondern in kleinen eigenen Programmen, den Servern. Damit nicht jede Agenten-App mit jedem Server anders sprechen muss, gibt es ein gemeinsames Protokoll, das Model Context Protocol, kurz MCP. Man kann es sich wie USB vorstellen: Jedes Gerät mit USB-Anschluss kann jeden USB-Stick lesen, und jede App, die MCP spricht, kann jeden MCP-Server benutzen. Für GitHub, Kalender oder Datenbanken gibt es fertige Server; für den Hofladen schreiben wir unsere eigenen, drei kleine Python-Dateien.

what an mcp server can offer

tools
functions the model calls by itself, such as the shop's sales
resources
data the app can read and put into the context, such as files
prompts
prepared instructions that a person picks from a list
in this experiment, the servers offer only tools.
Ein MCP-Server kann drei Arten von Dingen anbieten. Werkzeuge ruft das Modell selbst auf. Ressourcen sind Daten, die die App lesen und in den Kontext legen kann, etwa Dateien oder Datenbankeinträge. Prompts sind vorbereitete Anweisungen, die eine Person aus einer Liste wählt. Wir brauchen heute nur Werkzeuge; die beiden anderen Arten zeigen nur, dass MCP mehr ist als ein Werkzeugkasten.

an mcp server in python: tools/shop.py

from mcp_lite import FastMCP import lindenhof mcp = FastMCP("shop") @mcp.tool() def stock() -> dict: """How many units of each product are on the shelf right now.""" return lindenhof.stock() @mcp.tool() def sales(from_date: str, to_date: str) -> dict: """Units sold of each product between two dates (YYYY-MM-DD), both included.""" return lindenhof.sales(from_date, to_date) mcp.run()
one file per group of tools, in the folder tools; the file in the experiment also has the tool products
the file becomes an mcp server named shop; lindenhof holds the shop's data
@mcp.tool() turns the function below it into a tool: name, inputs and, in quotes, the description
what the function returns goes back to the agent as the tool's result
the server waits until opencode calls one of its tools
So sieht ein MCP-Server für den Hofladen aus, Zeile für Zeile. Oben wird aus der Datei ein Server mit dem Namen shop; lindenhof ist eine Datei im Startordner, die die Daten des Ladens bereithält und für das Experiment nicht gelesen werden muss. Jede Funktion mit @mcp.tool() darüber wird ein Werkzeug: Der Funktionsname wird zum Namen, die Parameter zu den Eingaben, und der Text in den dreifachen Anführungszeichen zur Beschreibung, die das Modell liest. Was die Funktion zurückgibt, ist das Ergebnis. mcp.run() startet den Server. FastMCP heißt genauso wie im offiziellen Python-Paket mcp; der Startordner bringt eine kleine Kopie mit, damit niemand etwas installieren muss.

switching the server on: opencode.jsonc

{ "agents": { "shop": { "model": "openai/gpt-6-luna", "permissions": [ { "action": "*", "resource": "*", "effect": "deny" }, { "action": "shop_*", "resource": "*", "effect": "allow" } ] } }, "mcp": { "servers": { "shop": { "type": "local", "command": ["python", "tools/shop.py"] } } } }
one file in the folder farm-shop configures the agent: model, rules and servers (shortened)
opencode starts the server with this command and asks it for its tools
a rule lets the agent use them: all tools whose names start with shop_
Damit der Agent die Werkzeuge bekommt, braucht es zwei Einträge in opencode.jsonc, der Konfigurationsdatei im Ordner des Ladens. Unter mcp steht der Server mit dem Befehl, mit dem OpenCode ihn startet; unter macOS steht dort python3. Und unter permissions eine Regel, die die Werkzeuge erlaubt, denn die erste Regel verbietet alles. Alles, was der Agent braucht, liegt in diesem einen Ordner; an globalen Einstellungen wird nichts geändert.

Für die Wochenbestellung bekommt der Agent vier Werkzeuge in zwei Gruppen. Drei lesen nur: die Produkte mit Lieferant, Packungsgröße und Haltbarkeit, den Bestand im Regal und die Verkäufe zwischen zwei Daten. Das vierte handelt: Es schickt eine Bestellung an einen Lieferanten; im Experiment landet sie als Datei im Ordner outbox. Lesen kann nichts kaputt machen, Bestellen kostet Geld. Deshalb bekommen die beiden Gruppen verschiedene Regeln.

what a tool may do

allow
the agent calls the tool whenever it decides to
ask
opencode stops before every call and asks the person
deny
the tool is gone, the model does not even see it
set per tool in opencode.jsonc, under the agent's permissions, for example:{ "action": "orders_*", "resource": "*", "effect": "ask" }
Jede Regel hat eine von drei Wirkungen. Lesen darf der Agent frei, shop steht auf allow. Bestellen kostet Geld und lässt sich nicht zurücknehmen, deshalb steht orders auf ask: OpenCode hält vor jeder Bestellung an und zeigt sie Jeff, der sie erlaubt oder ablehnt. Deny ist mehr als ein Verbot: Ein verweigertes Werkzeug verschwindet aus dem Kontext, das Modell weiß nicht einmal, dass es existiert. Die Regeln stehen in opencode.jsonc unter dem Agenten, und die letzte passende Regel gilt.

how jeff works out the weekly order

a skill writes such a process down, like the sheet you give a new helper on the first day.
Jeff bestellt nach festen Regeln, die er nirgends aufgeschrieben hat: Er nimmt die Verkäufe der letzten vier Wochen, rechnet den Durchschnitt pro Woche aus und will davon das Anderthalbfache im Regal haben, bei Frischware nur das Einfache, damit nichts verdirbt. Was fehlt, rundet er auf ganze Packungen auf, bestellt je Lieferant einmal und nie beim eigenen Hof, und vorher schaut er sich die Liste an. Einer neuen Aushilfe würde er genau das auf einen Zettel schreiben. Ein Skill ist dieser Zettel für den Agenten: keine neue Fähigkeit, nur das Wissen, wie dieser Laden die Arbeit macht.

a skill is a file with know-how

farm-shop/.agents/skills/weekly-order/SKILL.md
--- name: weekly-order description: How the Lindenhof farm shop works out its weekly order to the suppliers. Use it whenever an order or restocking is due. --- # Weekly order 1. Get the sales of the last four weeks with `sales` … 2. The target stock is the average per week times 1.5 … 3. The need is the target minus the units on the shelf (`stock`) … 4. Round the need up to a whole number of packs … 5. Make one order per supplier. Products from the own farm are never ordered. 6. Show the order as a table … and place it only after the owner has agreed.
Ein Skill ist eine Markdown-Datei in einem Ordner mit festem Namen. Oben, zwischen den Strichen, stehen Name und Beschreibung; diese beiden Zeilen sieht der Agent immer. Darunter stehen die Schritte in normaler Sprache, die sechs Schritte von eben. Kein Code, nur Anweisungen. Die vollständige Datei steht im Experiment zum Kopieren.

in the chat: the agent loads the skill first

Dieselbe Frage wie beim nackten Agenten, jetzt mit Skill. Bevor das Modell irgendein Werkzeug des Ladens aufruft, lädt es den Skill weekly-order. Danach ruft es die drei Werkzeuge genau so auf, wie der Skill es verlangt: Verkäufe der letzten vier Wochen, bis einschließlich gestern. Am Ende zeigt es die Tabelle und fragt, ob es bestellen soll, wie es im Skill steht.

the skill enters the context only when it is needed

Im Kontext steht zu Beginn vom Skill nur eine Zeile: Name und Beschreibung. Erst wenn die Frage zur Beschreibung passt, ruft das Modell das Werkzeug skill auf, und dann kommt der ganze Text in den Kontext, genau in dem Moment, in dem er gebraucht wird. So kann ein Agent Dutzende Skills kennen, ohne dass sein Kontext voll wird.

how does the model know when to load a skill?

description
says what the skill is for and when to use it · it is all the model sees beforehand
instructions
clear steps that name the tools · so that loading it pays off
model
strong enough to connect the question to the description · small models often miss it
Ob ein Skill geladen wird, entscheidet das Modell, und es hat dafür nur die Beschreibung. Deshalb steht in einer guten Beschreibung nicht nur, worum es geht, sondern auch, wann der Skill gebraucht wird: „Use it whenever an order or restocking is due.“ Die Anweisungen müssen dann so klar sein, dass sie das Ergebnis wirklich verbessern. Und das Modell muss stark genug sein, die Frage mit der Beschreibung zu verbinden; im letzten Teil sehen wir ein kleines Modell, das den Skill gar nicht erst lädt.

with the skill, both runs follow the shop's rules

a skill turns a model that invents its own rules into one that follows the rules of this shop.
Dieselbe Frage, zwei neue Sitzungen, jetzt mit dem Skill: Beide Läufe sehen vier Wochen an, beide kommen auf genau die Mengen, die das Prüfskript ohne Sprachmodell ausrechnet, und beide lassen den eigenen Hof weg. Nichts an den Werkzeugen hat sich geändert.

a command is a saved prompt with a short name

Jeff stößt die Bestellung jede Woche an, und jedes Mal müsste er denselben langen Prompt tippen, mit allen Bedingungen, damit nichts schiefgeht. Ein Command speichert diesen Prompt in einer Datei und gibt ihm einen kurzen Namen, wie eine Kurzwahltaste am Telefon. Jeff tippt nur noch /weekly-order, und OpenCode schickt den ganzen Text.

a command is a file, too

farm-shop/.opencode/commands/weekly-order.md
--- description: Work out this week's order and place it once the owner has agreed agent: shop --- Work out this week's order with the skill weekly-order, for these suppliers: $ARGUMENTS If no supplier is named, do it for all of them. Show me the table first and place one order per supplier only after I have agreed.
Der Dateiname wird zum Befehl. Die Beschreibung oben ist für Jeff: Sie steht in der Liste der Commands, wenn er einen Schrägstrich tippt. Die Zeile agent legt fest, welcher Agent den Command ausführt. Darunter steht der Prompt, den der Agent bekommt, und $ARGUMENTS ist der Platz für das, was hinter dem Befehl steht. Der Command nennt den Skill ausdrücklich; so muss sich das Modell nicht darauf verlassen, dass es ihn selbst findet.

what opencode sends to the agent

Jeff tippt eine Zeile, OpenCode liest die Datei, setzt den Rest der Zeile für $ARGUMENTS ein und schickt den ganzen Text an den Agenten. Das Modell sieht keinen Befehl, sondern nur einen ausführlichen Prompt, Wort für Wort aus der Datei. Danach läuft alles wie vorher: Skill laden, Werkzeuge aufrufen, Tabelle zeigen, und bei der Bestellung fragt OpenCode nach, weil orders auf ask steht.

who decides when each part comes in

tool
the model decides when to call it · the permission decides whether it may
skill
the model loads it when the description fits · or a command names it
command
a person types it · the model never starts one by itself
Das ist der eigentliche Unterschied zwischen den drei Teilen. Werkzeuge und Skills setzt das Modell selbst ein, eingeschränkt durch die Regeln in der Konfiguration. Einen Command startet nur ein Mensch. Wer einen Ablauf zuverlässig in Gang setzen will, schreibt einen Command; wer will, dass der Agent etwas von selbst richtig macht, schreibt einen Skill.

the daily closing, in jeff's words

every morning the cash box starts with 100 euros of change. customers pay cash into the box or by card at the self-service till; card payments never reach the box. whoever brings back a glass bottle or jar takes 15 cents of deposit out of the box. in the evening i count the box and compare it with what should be in it. a difference of up to two euros either way is fine, anything more i want to hear about. then the day goes into the cash book.
Der zweite Ablauf ist der Kassenabschluss am Abend. So beschreibt Jeff ihn, in seinen eigenen Worten. Alles, was ein Skill braucht, steht darin: das Wechselgeld, das Pfand, die Toleranz und der Eintrag ins Kassenbuch.

why not let the agent write the skill?

jeff can describe his job, but he would never write a skill file, while the agent knows its tools and how a skill is laid out.
so jeff describes the job in his own words, and the agent writes the skill and the command from them.
someone still has to read what the agent wrote before it runs every evening.
Den ersten Skill haben wir selbst geschrieben. Jeff würde das nie tun: Er kann seine Arbeit beschreiben, aber er schreibt keine Markdown-Dateien mit Kopfzeilen. Der Agent dagegen kennt seine Werkzeuge und weiß, wie ein Skill aufgebaut ist. Also beschreibt Jeff, und der Agent schreibt. Der Haken: Was der Agent schreibt, muss jemand lesen, bevor es jeden Abend läuft. Wie nötig das ist, zeigt der Versuch gleich.

three rules let the agent write, but only skills and commands

farm-shop/opencode.jsonc, under the agent shop, after the other rules
{ "action": "skill", "resource": "daily-closing", "effect": "allow" }, { "action": "edit", "resource": ".agents/skills/**", "effect": "ask" }, { "action": "edit", "resource": ".opencode/commands/**", "effect": "ask" }
Damit der Agent schreiben kann, kommen drei Regeln in dieselbe Datei opencode.jsonc im Ordner des Ladens; an globalen Einstellungen wird nichts geändert. Die erste erlaubt den Skill, den der Agent gleich schreibt. Die anderen beiden geben ihm ein Werkzeug zum Schreiben von Dateien, aber nur in den beiden Ordnern für Skills und Commands, und mit ask zeigt OpenCode jede Datei, bevor sie entsteht. Kassenbuch, Werkzeuge und die eigene Konfiguration bleiben für den Agenten tabu; sonst könnte er sich seine Rechte selbst erweitern.

Within ±€2.00 is acceptable. ## Procedure 1. Get the day's till register log and the counted cash amount for the same date … 4. Write the closing to the cash book …
Wir haben dem Agenten gesagt, dass Skill und Command nicht funktionieren, und ihn gebeten, sie mit weekly-order zu vergleichen. Er hat die Kopfzeilen ergänzt, und der Abschluss des 19. a second request: a report jeff can check

Extend the skill daily-closing: after the closing, write a clear one-page report of the day as reports/closing-<date>.typ in Typst, with every step and every intermediate result, so that I can check the closing, and turn it into a PDF with typst compile.
two more rules in opencode.jsonc: the agent may write in the folder reports and run exactly one command { "action": "edit", "resource": "reports/**", "effect": "allow" }, { "action": "shell", "resource": "typst compile reports/*", "effect": "allow" }
Eine Antwort im Chat ist mit der Sitzung weg. Jeff will eine Seite, auf der er jeden Schritt nachrechnen kann. Typst ist ein kleines Programm, das aus einer Textdatei ein PDF macht; es muss dafür installiert sein, das ist im Experiment ein freiwilliger Schritt. Der Agent darf jetzt in einen Ordner reports schreiben und genau einen Befehl ausführen, typst compile. Dann genügt eine zweite Bitte, und er erweitert seinen eigenen Skill.

a small model picks the tool whose name fits a word of the question, and it does not think of loading a skill by itself.
one run each; gemma models in lm studio
Fünf Fragen, je eine neue Sitzung, alle drei Gruppen von Werkzeugen und beide Skills sind da. gpt-6-luna wählt jedes Mal richtig und lädt für die Frage nach der Kasse von selbst den Skill daily-closing. the order that was never placed

coach
runs on gpt-6.2-sol, one of openai's largest models, reads the whole folder and rewrites skills and commands for the small model
gpt-6-luna ist selbst eines der kleineren Modelle von OpenAI, nur eben viel größer als eines, das auf einen Laptop passt. Für das Umschreiben der Anweisungen nehmen wir deshalb ein Frontier-Modell, gpt-6.2-sol. Es läuft als zweiter Agent, coach, im selben Ordner: Er darf alles lesen und Skills und Commands umschreiben, aber nichts ausführen, und er fragt vor jeder Änderung. Man erzählt ihm, was beim kleinen Modell schiefging, und bittet ihn, die Anweisungen so genau zu machen, dass ein kleines Modell sie Schritt für Schritt befolgen kann. Statt coach geht jeder starke Agent, etwa Claude Code mit Opus im selben Ordner.

the same rule, written for a small model

by hand, for gpt-6-luna
The target stock is the average per week times 1.5. For perishable products, with a shelf life of 7 days or less, it is the average times 1.0, so that nothing spoils.
by the coach, for gemma-4-e2b
If shelf_life_days <= 7, target = ceil(S / 4) (average × 1.0). Otherwise target = ceil(3 × S / 8) (average × 1.5).
Links die Regel, wie sie für gpt-6-luna gereicht hat, rechts dieselbe Regel, wie der Coach sie für das kleine Modell geschrieben hat: als Formel, mit S für die verkauften Stück aus shop_sales, und gerundet wird erst am Ende. Insgesamt hat gpt-6.2-sol in gut einer Minute alle vier Dateien umgeschrieben. Jeder Schritt nennt das Werkzeug mit seinen Argumenten, der Bestand muss aus shop_stock kommen, und die Bestellung geht erst nach einer ausdrücklichen Zustimmung in einer späteren Nachricht hinaus, eine je Lieferant. Der Kassenabschluss rechnet in ganzen Cent und prüft sein Ergebnis gegen die Werte der Werkzeuge. Die Beschreibung von daily-closing nennt jetzt auch die Fragen nach den Bareinnahmen und nach der Kasse, damit ein kleines Modell den Skill dort lädt. Die Regeln des Ladens sind dieselben geblieben; geändert hat sich nur, wie genau sie dastehen.

the small models with the coach's instructions

exact instructions fixed most of the mistakes, and the arithmetic that is left belongs in a tool, not in a skill.
one run each; gemma models in lm studio
Dieselben fünf Fragen und beide Commands, je eine neue Sitzung, jetzt mit den Dateien des Coachs. Beide Modelle nehmen für die Bareinnahmen jetzt till_register_log, und keines meldet mehr eine Bestellung, die abgelehnt wurde. gemma-4-e4b lädt für die Kassenfrage den Skill und findet die −4,50 Euro, liest bei /weekly-order den Bestand mit shop_stock, lässt den eigenen Hof weg und wartet auf die Zustimmung; es verrechnet sich aber noch bei sechs von neun Mengen, etwa 48 statt 30 Gläser Joghurt. Den Kassenabschluss schreibt es richtig ins Kassenbuch. gemma-4-e2b trifft jetzt alle neun Bestellmengen und wartet auf die Zustimmung, lädt bei der Kassenfrage aber weiterhin keinen Skill und vergisst beim Abschluss den letzten Schritt: Es rechnet die −4,50 Euro aus, schreibt sie aber nicht ins Kassenbuch. Was übrig bleibt, ist Rechnen und Durchhalten bis zum letzten Schritt. Was sich genau festlegen lässt, etwa die Zielmenge je Produkt, gehört in ein Werkzeug, das in Code rechnet; das ist eine der Erweiterungen im Experiment.

what to take away

  • tools give the agent access to the shopa function with a name, inputs and a description, offered through mcp
  • a skill tells it how this shop does the jobloaded only when the description fits
  • a command gives a person a short way to start ita saved prompt, never started by the model
  • rules decide what the agent may doallow, ask or deny, in opencode.jsonc
  • read what an agent wrote before it runsand check results where the tools leave them
  • the smaller the model, the more exact the instructions
Die sechs Punkte zum Mitnehmen, einer nach dem anderen abhaken. Zusammen mit dem Modell und der Schleife, die Werkzeugaufrufe ausführt und Ergebnisse zurückgibt, ist das ein Agent, der eine echte Arbeit übernehmen kann, und zwar so, wie dieser Laden sie macht.
