A printer's type case looks like a mess of tiny compartments, and yet a typesetter finds every letter blind, because each column holds one kind of thing and every compartment has its place. R keeps data in the same way: a table is a row of columns, and each column holds values of exactly one kind. Once you see this, most of what R does with data stops being a surprise.
First the big picture: which shapes data takes in R, and the example that runs through the whole deck.

four shapes of data

in a matrix every cell has the same type, in a data frame every column has its own.
A single value, here the number 2, is rare in data analysis. First key: almost everything comes as many values of the same kind, a vector; the single value is called a scalar. Second key: a matrix puts several vectors of one type side by side into a block, which suits numbers but not a table in which one column holds numbers and another words. Third key: that is what the data frame is for, and it is where we are heading. The matrix stays on this slide; in exploratory analysis you will hardly need it.

one game, four facts

image: ai-generated (gpt-image-2.5-flare)
Our example for the whole session is the game with three doors, known as the Monty Hall problem. A car stands behind one door, goats behind the other two. You pick a door, the host, who knows where the car is, opens another door with a goat behind it, and you decide whether to stay with your door or switch to the last closed one. Every game can be written down as four facts: where the car was, which door was picked first, which door the host opened and whether the player stayed or switched. Whether staying or switching is better is the question of the project, and the data will answer it, not us.

rounds as vectors

prize_door <- c(2, 1, 3, 3, 1) contestant_choice <- c(2, 3, 1, 1, 1) monty_opens <- c(1, 2, 2, 2, 3) decision <- c("stay", "switch", "stay", "switch", "switch")
c() combines values into a vector, and the first value of each vector belongs to the first round.
Here are five rounds, written the way the game writes them. The function c(), for combine, puts values together into a vector, and the arrow gives the vector a name. Each line is one fact, each position one round: the first value of every vector belongs to round one, the second to round two, and so on.
Now the vector itself: what holds it together, which types there are, and what you can do with a whole vector at once.

the same position, the same round

four vectors of the same length describe five rounds, as long as nobody mixes up the order.
The four vectors one below the other, the positions 1 to 5 above them. First key: position 1 in all four vectors is round 1, in which the car was behind door 2, the player picked door 2, the host opened door 1 and the player stayed. Second key: position 4 is round 4, in which the car was behind door 3, the player picked door 1, the host opened door 2 and the player switched. Nothing in R ties the first value of prize_door to the first value of decision; only the position does. That works as long as all four vectors have the same length and the same order, and a data frame, later, is the structure that guarantees exactly that.

one vector, one type

every value in a vector has the same type, and typeof() tells you which one.
Hands-On Programming with R calls these atomic vectors: the smallest building block of data in R, and always of one type. Numbers you type are doubles, numbers with a decimal point or without. Whole numbers with an L, or whole numbers read from a file, are integers. Text in quotes is character, and TRUE and FALSE are logical. The colours stay with these four types for the rest of the deck. There are two more types, complex and raw, which you will hardly meet in data analysis. A second function, class(), says what a vector is meant to be, for example numeric or factor; for the four basic types typeof() is the honest answer.

asking a vector

length(prize_door) # 5 typeof(decision) # "character" mean(prize_door) # 2 table(decision) # stay 2, switch 3
sum, mean, median, min, max, range, sd, sort, unique, table: functions that take a whole vector at once.
Many functions take a whole vector and return one answer about it. length() counts the values, typeof() names the type, mean() averages, table() counts how often each value occurs; R prints that as a small table, here two rounds stayed and three switched. The list below the code names the ones you will use most often. The mean of the prize doors, 2, shows that a function computes whatever you ask, whether it means something or not: door numbers are labels, and their mean is meaningless.

when types meet

R never mixes types in a vector, it quietly converts to the most general one.
What happens if you combine values of different types? First key: a number and a logical value become two numbers, because TRUE counts as 1; the vector is a double. Second key: as soon as one text value joins in, everything becomes text, the 1 becomes the text "1" and TRUE the text "TRUE". The order behind it is logical, then double, then character, and R always picks the most general type that holds every value. This rule from Hands-On Programming with R explains many surprises later: one stray text value in a column of numbers, a dash or "n/a", and the whole column becomes text, so mean() no longer works. When a column has the wrong type, look for the one value that pulled it there.

comparing whole vectors

an operation on two vectors works position by position, with no loop to write.
Was the first pick already right? On the key, R compares prize_door and contestant_choice position by position, the first with the first, the second with the second, and writes one answer per position. The result is a logical vector of the same length, TRUE where the two were equal. This is the most useful habit of R: arithmetic and comparisons work on whole vectors at once, and you never write a loop for it.

counting with TRUE and FALSE

first_pick_right <- prize_door == contestant_choice sum(first_pick_right) # 2 mean(first_pick_right) # 0.4
R counts TRUE as 1 and FALSE as 0, so the mean of a logical vector is a share.
We keep the comparison under a name. sum() counts the TRUE values, because R counts TRUE as 1 and FALSE as 0: in two of five rounds the first pick was right. mean() divides by the length and gives the share, 0.4. R for Data Science devotes a chapter to logical vectors for a reason: almost every question about data passes through one.

picking values by position

decision[1] # "stay"
decision[-1] # all but the first
decision[2:4] # "switch" "stay" "switch"
decision[c(1, 3)] # "stay" "stay"
square brackets select, a minus leaves out, and the result is again a vector.
Square brackets pick values from a vector by their position. Line by line: the first value; with a minus everything except the first; a range from the second to the fourth; and with c() any positions you like, here the first and the third. Whatever comes out is again a vector, so you can keep working with it. R starts counting at 1, not at 0 as Python does.

picking values by a condition

a logical vector in square brackets keeps exactly the positions that are TRUE.
Above, the rounds in which the player stayed, as a logical vector; below, whether the first pick was right. On the key, the logical vector goes into the square brackets: every position with FALSE above drops out, and the two rounds in which the player stayed remain. One of them was won, because whoever stays wins exactly when the first pick was right. This is how you will answer the project question: take the wins, keep only the rounds in which the player stayed, then only those in which the player switched, and compare the shares.

when a value is missing

NA means "not known", so anything computed with it is not known either, until you say what to do.
A round in which nobody wrote down the host's door is not a door 0; it is missing, and R marks it with NA, not available. The mean of 2, an unknown value and 3 is unknown, so R answers NA. With na.rm = TRUE you tell it to leave missing values out, and the mean of 2 and 3 is 2.5. R for Data Science treats missing values as a topic of their own because they spread through every calculation; is.na() finds them, and the decision whether to leave them out is yours. On the right three relatives that look similar but mean something else: NULL is nothing at all, NaN is the result of an impossible calculation such as 0 divided by 0, and Inf is infinity, for example 1 divided by 0.

factors: text with fixed levels

decision_factor <- factor( decision, levels = c("stay", "switch") ) levels(decision_factor) # "stay" "switch"
a factor knows all its possible values and their order, even those that do not occur.
For a variable with a fixed set of values, such as stay and switch, a factor is the better type. It knows its levels and their order, which tables and plots respect; a value outside the levels becomes NA instead of a silent new category, which catches typos; and table() counts a level even if it does not occur. The package forcats, part of the tidyverse, offers functions to reorder and combine levels.
a vector is a row of values of one type, and position i belongs to observation i.
That is all a vector is. Everything we did, comparing, counting, picking, works because the values share one type and because position i belongs to the same round, the same person, the same observation in every vector.
Now the vectors come together in a table, and the table takes over the promise we had to keep by hand: same length, same order. We need the data frame as an idea, not as a set of operations; we work with the tibble, the table of the tidyverse.

vectors become a table

games <- data.frame(prize_door, contestant_choice, monty_opens, decision)
a data frame is a list of equally long vectors, and every vector holds values of one type.
The four vectors, each in the colour of its type. First key: data.frame() puts them side by side, their names become the header, and R numbers the rows. Second key: one row is one game, and one column is one vector. This is the central sentence of the session, and it is how both books describe the data frame: a list of equally long vectors. The table guarantees what we had to promise ourselves before: all columns have the same length, and row 4 is round 4 in every column. And because every column is a vector, every column has one type, but different columns may have different ones.

tidy data

after Wickham, Çetinkaya-Rundel & Grolemund: R for Data Science, chapter "data tidying"
when a table is tidy, every column is a vector of one variable, and the tools of R fit it.
R for Data Science calls a table tidy when three rules hold: each variable is a column, each observation is a row, and each value is a cell. Our game table is tidy: one row per game, one column per fact. Data from the wild often is not, for example with one column per year or two facts in one cell, and then it has to be reshaped first. The reward for tidy data is that every column is a vector, and every tool from this deck and from dplyr fits it.
