What an AI agent is, how it differs from a chatbot such as ChatGPT or Claude in the browser, and what that means when it works on your research paper. The one sentence to take home: an agent is a language model that runs tools in a loop until a goal is reached, so it can act in your folder, and that makes it useful and makes you responsible for every step it takes.
Four parts: the difference to a chatbot, what an agent is made of, one run of an agent on a paper in Quarto, and how far agents get today, with the risks of working with one and what helps against each.

A chatbot is like a consultant on the phone: it tells you what to do, and you do it. An agent is like someone you hand the keys to your office: it opens the files itself, reads them, changes them and runs programs. That is why it can do so much more, and why it matters what you let it do.
First the difference, which lies not in the model but in who takes the next step.

chatbot and agent

With a chatbot you write a prompt, the model writes an answer, and the next step is yours: you copy the R code into your script, run it, and paste the error message back. With an agent you give a goal, and the model calls tools itself, looks at the results and carries on until the goal is reached: it reads your script, runs it, sees the error and fixes it. The loop between model and tools sits below the model, and at the end there is a result, as at the end of the chatbot there is an answer. Under the hood it can be the same language model; the difference is what is built around it.

a working definition

an ai agent runs tools in a loop to achieve a goal.
after Simon Willison, 18 september 2025
Three words carry the definition. Tools: the agent can read and write files, run programs and search the web. Loop: it looks at what a tool returned and decides on the next step itself. Goal: you say what you want, not how to get there. Anthropic describes agents in almost the same words, as language models that use tools based on feedback from their environment in a loop.
Now the inside of an agent, built up step by step, with the goal of getting feedback on the introduction of a paper.

the goal and the model

At the start a goal and a language model. On its own the model can only produce text; it cannot open a file. Then the tools: read, edit, write, bash for running programs such as R or Quarto, and web search. The model only writes down which tool it wants to call with which arguments; the program around it carries out the call on your computer. Then the loop: the result of every call goes back to the model, which thinks, acts again and observes again. In research this pattern is called ReAct, and it is the core of every agent.

memory, plan and instructions

Everything the agent knows during a run sits in its context window: the goal, every file it has read and every result. It fills up with each file, and when it is full, the agent has to summarize or forget. The plan is a list the agent writes and ticks off, a tool like any other. Instructions in text files are loaded at the start: a file called AGENTS.md says what the agent should know about the project, skills describe how you want certain things done and are loaded only when a task needs them, and commands are prepared instructions for what you often need, such as feedback on a paper. Then everything is together, and only the loop is highlighted, because it is what makes the model an agent. The last step shows the whole picture in full color.

the harness

Everything around the model is called the harness, like the harness that hitches a horse to a cart: the model provides the power, the harness steers it. It runs the loop, carries out the tool calls, manages the context window, loads AGENTS.md, skills and commands, and asks you for permission. OpenCode, Claude Code and Codex are harnesses, and many of them let you choose the model. An AI agent is a language model plus a harness.
Now one run of an agent on a paper in Quarto, as its log shows it, and the setting that decides what it may do without asking.

one run, as the log shows it

You give a goal in one sentence. Every tool call is marked with the tools icon. The agent reads the central file of the paper and finds that the sections live in files of their own, so it reads the introduction. Then it answers: the research question stands in the second paragraph instead of at the end. Nothing has changed in your files so far. Only when you ask it to move the question does it want to edit the file, and the harness stops and asks you: allow once, allow always, or reject. Before you allow, you see the change as a diff, line by line.

what it may do without asking

"permission": { "edit": "ask", "bash": "ask" }
in the settings of the harness, here opencode.json
reading is allowed, and changing a file or running a program waits for your yes.
The harness has settings for what the agent may do on its own. With these two lines, it may read your files freely but has to ask before it edits a file or runs a command in the shell. You can loosen this, for example allow it to always run R, but the safest start is to let it ask and to read what it wants to do before you say yes.
How long are the tasks agents can finish today, and what can go wrong when one works in your folder?

how long the tasks are that agents finish

METR, time horizon 1.1: software, machine learning and security tasks; above 16 h the measurement is unreliable
agents now finish tasks that take an expert many hours, but only half the time, so you check what they deliver.
METR measures how long a task may be before an agent fails at it. The length is the time a human expert needs; the time horizon is the length at which the agent succeeds half the time (blue) or four times out of five (light). GPT-4 managed tasks of about 4 minutes in 2023, Claude 3.7 Sonnet about an hour in early 2025, Claude Opus 4.6 about 12 hours and Claude Mythos Preview about 17 hours in spring 2026. Since 2023 the time horizon has doubled about every four months. At 80 percent success the tasks are much shorter, about 3 hours for the best model. Two caveats: the tasks come from software, machine learning and IT security, are well specified and scored automatically, and METR itself says that values above 16 hours are unreliable with its current tasks. For your paper this means: an agent can do long stretches of work on its own, and it fails on a good share of them, so its results are drafts you check.

what can go wrong, and what helps

Eight risks, each with what helps against it. An agent can delete or overwrite files, so work in a Git repository or on a copy. It can run a harmful command, so let it ask and approve every command. It treats text it reads in a web page or a file as possible instructions, which is called indirect prompt injection (Greshake et al., 2023) and has no complete protection yet, so read what it wants to do before you allow it. Its code can run and still compute the wrong thing, so check one number by hand. It can cite sources that do not exist, so open every reference you cite. Whatever it reads goes to the provider of the model, so keep personal data out of the folder. It tends to settle for basic analyses (Gu et al., 2024), so decide on variables and method yourself. And if it writes most of the paper, you lose track of your own work, so read every change before you accept it, because you answer for the paper.
